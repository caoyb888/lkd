# 莱矿-档案管理系统前端改造开发计划

## 概述

本计划基于既有 Vue 3 + Element Plus 前端实现，将其全面改造为 **React 18 + Tailwind CSS** 技术栈，核心目标是实现 **「一套代码覆盖双端」**：同一份源码通过 Tailwind 的响应式前缀（`sm:` `md:` `lg:` `xl:`）自动适配手机、平板、电脑三种终端，彻底告别 PC/移动端两套代码的维护负担。

改造遵循《莱矿-档案管理系统 CLAUDE.md》及《前端页面开发计划.md》中的业务功能、接口契约、权限矩阵与状态机定义，仅替换前端技术实现层，后端 API 与数据库保持零改动。

---

## 一、改造范围与目标

| 维度 | 现状 | 改造目标 |
|---|---|---|
| **框架** | Vue 3 (Composition API) + `<script setup>` | React 18 (函数组件 + Hooks) |
| **组件库** | Element Plus 2.x（重型组件库） | Tailwind CSS + Headless UI / Radix Primitives + shadcn/ui 模式 |
| **状态管理** | Pinia + pinia-plugin-persistedstate | Zustand + persist middleware |
| **路由** | Vue Router 4 (History 模式) | React Router v6 (Data APIs) |
| **HTTP** | Axios 封装 + 响应拦截器 | Axios 封装 + React Query (TanStack Query) |
| **样式方案** | SCSS + CSS 变量 + Element Plus 主题 | Tailwind CSS 3.4 + CSS 变量（原子化 + 响应式） |
| **表格** | Element Plus Table | TanStack Table (React Table) + Tailwind |
| **表单** | Element Plus Form（命令式校验） | React Hook Form（性能优先） + Zod（Schema 校验） |
| **构建工具** | Vite 5 | Vite 5（继续沿用） |
| **类型系统** | TypeScript 5 | TypeScript 5（严格模式保持） |

### 核心交付目标

1. **一套代码三端适配**：手机端（< 768px）、平板端（768px–1024px）、电脑端（> 1024px）共用同一套 React 组件源码。
2. **UI 风格延续**：保留「活力新知风」主色调（青绿 `#14B8A6`、暖橙 `#FB923C`），通过 Tailwind 的 `tailwind.config.js` 扩展品牌色，实现无缝视觉过渡。
3. **功能等价**：改造后所有页面功能、权限控制、审批流、数据字典缓存、打印导出与现有 Vue 版本完全一致。
4. **性能提升**：借助 React Query 的缓存与去重、React Hook Form 的非受控组件特性，首屏 LCP 目标 ≤ 1.5s。

## 二、响应式双端适配策略（核心方案）

Tailwind 采用 **Mobile-First** 设计哲学，天然支持从手机基线向上扩展，无需维护两套布局代码。

### 2.1 断点定义

| 断点名 | 宽度 | 对应设备 | Tailwind 前缀 |
|---|---|---|---|
| 默认 | < 640px | 手机竖屏 | 无前缀（基线） |
| `sm` | ≥ 640px | 手机横屏 / 小平板 | `sm:` |
| `md` | ≥ 768px | 平板竖屏 | `md:` |
| `lg` | ≥ 1024px | 平板横屏 / 小笔记本 | `lg:` |
| `xl` | ≥ 1280px | 桌面显示器 | `xl:` |
| `2xl` | ≥ 1536px | 大屏显示器 | `2xl:` |

### 2.2 三端布局映射

#### 导航体系

```
电脑端 (lg:+)                平板端 (md~lg)              手机端 (<md)
┌────────┬──────────────┐   ┌────────┬──────────────┐   ┌──────────────┐
│ 侧边栏  │   内容区      │   │可收起侧边│   内容区      │   │  顶部标题栏   │
│ 220px  │  padding:24px│   │  图标栏  │  padding:20px│   │  +汉堡菜单   │
│ 文字菜单│              │   │         │              │   ├──────────────┤
└────────┴──────────────┘   └────────┴──────────────┘   │ 底部 Tab 栏   │
                                                         │  首页/案卷/借阅/我的 │
                                                         └──────────────┘
```

- **电脑端**：固定左侧 sidebar，展开文字菜单，顶部 header 常驻。
- **平板端**：sidebar 默认收起为图标栏，点击展开遮罩抽屉；内容区栅格从 3 列降为 2 列。
- **手机端**：sidebar 完全隐藏，变为顶部汉堡菜单 + 底部固定 Tab 导航栏（档案/借阅/我的），内容区单列铺满。

#### 列表/表格视图

| 设备 | 展示方式 | Tailwind 实现 |
|---|---|---|
| 电脑端 | 标准表格（多列） | `hidden md:block` |
| 平板端 | 紧凑表格（减少列）或卡片网格（2 列） | `md:grid md:grid-cols-2 lg:hidden` |
| 手机端 | 卡片列表（单列，纵向堆叠） | `grid grid-cols-1 md:hidden` |

**关键实现示例**：

```tsx
// 案卷列表页：表格与卡片列表共用同一数据源，按断点切换渲染
<div className="hidden md:block">
  <DataTable columns={columns} data={records} /> {/* TanStack Table */}
</div>
<div className="grid grid-cols-1 gap-4 md:hidden">
  {records.map(r => <VolumeCard key={r.recordId} data={r} />)}
</div>
```

#### 检索/筛选区

- **电脑端**：筛选表单横向平铺，`flex-row` 展开所有条件。
- **平板端**：筛选项换行，`flex-wrap`。
- **手机端**：筛选区折叠为顶部一个「筛选」按钮，点击后从底部滑出 Drawer（Headless UI Dialog + 底部定位），内部纵向堆叠筛选条件。

```tsx
<div className="hidden md:flex md:flex-wrap md:gap-3">
  {/* 电脑端平铺筛选 */}
  <YearSelect /> <CategorySelect /> <StatusSelect />
</div>
<MobileFilterDrawer className="md:hidden">
  {/* 手机端抽屉内筛选 */}
  <YearSelect /> <CategorySelect /> <StatusSelect />
</MobileFilterDrawer>
```

### 2.3 表单页响应式

- **电脑端**：表单字段多列栅格（`lg:grid-cols-3`），宽屏舒适。
- **平板端**：降为 2 列（`md:grid-cols-2`）。
- **手机端**：单列纵向（`grid-cols-1`），输入框 100% 宽度，底部固定操作栏（sticky bottom）。

```tsx
<form className="grid grid-cols-1 gap-6 md:grid-cols-2 lg:grid-cols-3">
  <FormField name="fondsNo" label="全宗号" />
  <FormField name="year" label="年度" />
  <FormField name="categoryL1" label="一级类目" />
  {/* ... */}
</form>
```

## 四、核心机制改造方案

### 4.1 状态管理：Zustand 替代 Pinia

| 能力 | Pinia (Vue) | Zustand (React) |
|---|---|---|
| Store 定义 | `defineStore()` | `create<T>()(...)` |
| 持久化 | `pinia-plugin-persistedstate` | `persist` middleware |
| 响应式读取 | `computed(() => ...)` | 直接在组件 `useStore(state => state.xxx)` 中选取 |
| 字典加载 | `loadAll()` action | `fetchDicts()` action，配合 React Query 自动缓存 |

**字典 Store 改造示例**：

```tsx
// stores/dictStore.ts
import { create } from 'zustand'
import { persist } from 'zustand/middleware'
import { DictApi } from '@/api/system/dict'
import type { DictItemVO } from '@/types/vo'

interface DictState {
  dictMap: Record<string, DictItemVO[]>
  loaded: boolean
  loadAll: () => Promise<void>
  getItems: (code: string) => DictItemVO[]
  getLabel: (code: string, value: string) => string
}

export const useDictStore = create<DictState>()(
  persist(
    (set, get) => ({
      dictMap: {},
      loaded: false,
      loadAll: async () => {
        const data = await DictApi.allMap()
        set({ dictMap: data, loaded: true })
      },
      getItems: (code) => get().dictMap[code]?.filter(i => i.status === 1) ?? [],
      getLabel: (code, value) =>
        get().dictMap[code]?.find(i => i.itemValue === value)?.itemLabel ?? value,
    }),
    { name: 'lkda_dict' }
  )
)
```

### 4.2 服务端状态：React Query 替代裸 Axios

原有 Vue 版本中每个页面组件在 `onMounted` 中手动调用 `loadList()`。改造后，列表数据通过 **TanStack Query** 管理：

```tsx
// hooks/useVolumeList.ts
import { useQuery } from '@tanstack/react-query'
import { VolumeApi } from '@/api/volume'
import type { VolumeQueryDTO } from '@/api/volume'

export function useVolumeList(params: VolumeQueryDTO) {
  return useQuery({
    queryKey: ['volume', 'list', params],
    queryFn: () => VolumeApi.page(params),
    staleTime: 30_000,
  })
}
```

**收益**：
- 自动去重：300ms 内相同参数不重复请求（替代原 `dedupRequest`）。
- 自动缓存：返回列表页时展示缓存数据，后台静默刷新。
- 自动重试：网络异常时自动重试 3 次。
- 分页保持：翻页后返回，记忆此前页码与筛选条件。

### 4.3 路由与权限：React Router v6 Data API

```tsx
// routes/index.tsx
import { createBrowserRouter, redirect } from 'react-router-dom'
import { useAuthStore } from '@/stores/authStore'
import { useDictStore } from '@/stores/dictStore'

const authLoader = async () => {
  const { token } = useAuthStore.getState()
  if (!token) return redirect('/login')
  // 字典预加载（与既有路由守卫等价）
  const { loaded, loadAll } = useDictStore.getState()
  if (!loaded) await loadAll().catch(() => {})
  return null
}

export const router = createBrowserRouter([
  {
    path: '/',
    element: <MainLayout />,
    loader: authLoader,
    children: [
      { path: 'dashboard', element: <DashboardView />, loader: /* ... */ },
      { path: 'volume/list', element: <VolumeListView /> },
      // ...
    ],
  },
  {
    path: '/login',
    element: <AuthLayout />,
    children: [{ index: true, element: <LoginView /> }],
  },
])
```

**权限守卫**：通过路由 `loader` + 组件内 `useAuth()` Hook 双重判断，与既有规范一致。

### 4.4 表单体系：React Hook Form + Zod

替代 Element Plus 的 `el-form` 命令式校验：

```tsx
import { useForm } from 'react-hook-form'
import { zodResolver } from '@hookform/resolvers/zod'
import * as z from 'zod'

const schema = z.object({
  applyCount: z.number().min(1).max(availableCopies),
  planReturnDate: z.string().min(1, '请选择归还日期'),
  reason: z.string().min(5, '至少 5 个字'),
})

function BorrowApplyForm() {
  const { register, handleSubmit, formState: { errors } } = useForm({
    resolver: zodResolver(schema),
  })
  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('reason')} className="rounded-lg border border-slate-200 ..." />
      {errors.reason && <span className="text-red-500 text-sm">{errors.reason.message}</span>}
    </form>
  )
}
```

## 六、响应式改造关键决策清单

| 决策点 | 方案 | 理由 |
|---|---|---|
| 手机端表格 → 卡片列表，数据量大了怎么办？ | 卡片列表同样使用 TanStack Virtual 虚拟滚动 | 保持手机端流畅，万级数据不卡顿 |
| 手机端底部 Tab 导航与侧边栏菜单如何对应？ | 底部仅放 4 个高频入口（首页/案卷/借阅/我的），其余收进「我的」页面内的网格菜单 | 减少认知负担，参考钉钉/企业微信 |
| 表单在手机端是否分页（Wizard）？ | 不分页，纵向滚动 + sticky 底部操作栏；超长表单（如案卷 4 区）使用折叠面板（Accordion） | 减少页面跳转，保持上下文连续 |
| 日期/选择器在手机端如何交互？ | 统一使用底部弹窗（Bottom Sheet）形式，由 Radix Dialog + 底部定位动画实现 | 符合移动端单手操作习惯 |
| 打印预览在手机端是否可用？ | 可用，但提示「建议使用电脑端获得最佳打印体验」；预览区支持双指缩放 | 不阻塞功能，但引导用户使用场景 |
| 是否需要 PWA / 离线能力？ | 一期不做，但 Service Worker 脚手架预留（Vite PWA 插件） | 降低改造复杂度，二期可平滑升级 |

## 七、质量门禁（改造专项）

| 检查项 | 标准 |
|---|---|
| **响应式覆盖** | 每个页面必须在 Chrome DevTools 的 iPhone SE / iPad Air / Desktop 三种视口下完成人工走查 |
| **TypeScript 严格度** | 禁止 `any`，组件 Props 必须显式接口定义 |
| **组件封装** | 业务页面禁止直接使用 Radix 原始组件，必须通过 `components/ui` 封装层 |
| **类名规范** | 优先使用 Tailwind 原子类；复杂逻辑类名使用 `cn()`（`clsx` + `tailwind-merge`）合并 |
| **字典加载** | 禁止在业务组件内直接调用字典 API，必须通过 `useDictStore().getItems()` |
| **权限校验** | 按钮显隐基于 `useAuthStore().hasRole / hasPermission`，路由 loader 做第一层拦截 |
| **打包体积** | 单 chunk ≤ 400KB，总 gzip ≤ 1.5MB（React 生态较 Vue 略大，需更严格拆分） |
| **性能指标** | Lighthouse 性能 ≥ 90，可访问性 ≥ 95，首屏 LCP ≤ 1.5s |
| **交互细节** | 所有按钮必须有 `active:scale-[0.98]` 或 `active:bg-primary-dark` 触摸反馈 |

## 八、风险与回滚策略

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| React 18 + 新生态学习成本 | 团队熟悉 Vue，改造初期效率低 | Sprint R1 预留 3 天组件库搭建期，产出可复用 Demo；Code Review 强制由熟悉 React 的成员参与 |
| Tailwind 类名爆炸 | HTML 可读性下降 | 强制使用 `prettier-plugin-tailwindcss` 自动排序；复杂组件抽离为原子组件 |
| 手机端交互适配遗漏 | 某些页面在手机上无法操作 | 每个 Sprint 末期固定 0.5 天「手机端走查日」 |
| 第三方组件库（Radix）升级 Breaking Change | 基础组件库失效 | Radix 1.x 已稳定，锁定版本；关键组件（Dialog/Select）自行封装一层，隔离底层 |
| 改造周期超预期 | 影响 UAT 上线 | 采用「增量替换」策略：改造期间 Vue 版本继续维护，React 版本并行开发，R4 完成后再切换 Nginx 路由指向新 `dist/` |

**回滚方案**：
- 改造期间 Vue 版本代码保留在 `lkda-web/` 目录（原目录不动）。
- React 新版本开发在 `lkda-web-react/` 目录。
- 上线时仅需修改 Nginx 配置，将静态资源根目录从 `lkda-web/dist` 指向 `lkda-web-react/dist`，**5 分钟内可回滚**。

## 九、附录：既有类型与 API 复用指南

后端接口、`Result<T>` 响应结构、VO/DTO 类型定义在改造中**完全复用**，仅需将 `.d.ts` 文件复制至新工程的 `src/types/` 目录。

需要调整的点：
- Vue 的 `Ref<T>` / `ComputedRef<T>` 类型删除，改为 React 的 `useState` / `useMemo` 原生类型推导。
- Pinia Store 类型改为 Zustand `create<State & Actions>()`。
- Vue Router 的 `RouteMeta` 类型改为 React Router 的 `RouteObject` meta。
